1. Overview

NovaLearn is a Grade 1 math learning app used by a child under a parent's account. The parent registers, adds a child profile, and the child works through lessons, an AI-backed tutor, and a homework helper while the parent reviews progress on a dashboard. This policy covers exactly what the backend and mobile app store, send to third parties, and never collect — each claim below is traceable to a specific part of the running application, not aspirational language.

2. Parent account data

Collected once, at registration, from the parent only.

  • emailused to sign in and as the account identifier.
  • passwordnever stored as entered — only a one-way bcrypt hash is kept; the original password cannot be recovered from the database.
  • session tokensa short-lived access token (1 hour by default) and a longer-lived refresh token. The refresh token is itself stored only as a hash and rotates — made invalid and replaced — every time it's used.

3. Child profile data

Entered by the parent when adding a child. A child never fills out their own profile.

  • display namecan be a nickname — nothing requires a legal name.
  • birth dateused to default the grade level and age-appropriate content.
  • grade level, avatar, learning preferencesthe avatar is always one of five illustrated characters the parent picks — never an uploaded photo.
  • lesson activitywhich lessons and exercises were attempted, scores, and time of each attempt — this is what powers the parent dashboard.
  • tutor & homework questionsthe text a child types or speaks to ask NovaLearn for help — see §5 for exactly where this goes.
  • coins, streaks, badgesthe gamification record — an append-only ledger of rewards earned, not a profile of behavior used for anything beyond showing progress back to the parent.

4. What is never collected

Data minimization isn't a policy promise here — these fields simply don't exist anywhere in the application's data model.

Exists in the app

  • Nickname, birth date, grade, chosen avatar
  • Lesson progress & scores
  • Tutor / homework question text
  • Coins, streak count, badges earned

Not in the app

  • Child email address or phone number
  • Home address or precise location
  • Photo of the child, or any camera access
  • Advertising ID or cross-app tracking identifier
  • Voice recordings — speech-to-text runs on-device and the audio is never uploaded

5. The AI tutor and homework helper

This is the one place a child's words can leave NovaLearn's own servers, so it gets specific treatment. Before anything is sent anywhere, the question is checked against a safety filter; anything flagged is answered with a safe redirect and never reaches an AI provider at all.

If no AI provider is configuredPre-written offline answers are used. Nothing leaves the server.
If Anthropic is configuredThe question (and only the question — no account email, no other child's data) is sent to Anthropic's API to generate the explanation.
If Google Gemini is configuredSame question-only scope. On Gemini's free tier specifically, Google's own terms permit using submitted content to improve their products — this is disclosed in the technical config and should not be the default for a real launch without a billing-enabled account that carries a stronger data-use guarantee.

A real AI response is treated as untrusted, exactly like the child's own input: it passes back through the same safety filter and is capped in length before anything reaches the child's screen.

6. How data is protected

  • passwordsbcrypt-hashed; plaintext is never logged or stored.
  • refresh tokensstored only as a SHA-256 hash, single-use, rotate on every login.
  • authorizationevery request for a child's data is checked server-side against which parent account actually owns that child — this check cannot be bypassed from the app's UI.
  • rate limitinglogin attempts and AI requests are both throttled per account to blunt brute-force and runaway-cost scenarios.
  • request logginga correlation ID ties log lines from one request together for debugging — it is not a behavioral or advertising identifier, and logs do not store question content.

7. Retention and deletion

A parent can permanently delete the account at any time, after re-entering their password. Deletion removes the parent record and — automatically, at the database level, not as a separate manual step that could be missed — every child profile, every lesson attempt, every reward, and every session token tied to that account. There is currently no self-serve mobile screen for this yet; it's reachable today through the account API directly.

8. Children's privacy & consent

NovaLearn's design assumes the parent-managed account structure — a parent registers, and only a parent can add, view, or delete a child profile — serves as the mechanism for parental consent and control required by laws like COPPA (US) and similar frameworks elsewhere. That assumption has not yet been confirmed by legal counsel and should not be treated as settled until it is. No advertising or behavioral-tracking SDK is integrated, which removes the most common source of COPPA exposure for a children's app, but data-collection minimalism alone does not constitute legal compliance.
